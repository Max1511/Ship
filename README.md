## Проект выполнен в рамках тестового задания для Junior Unity Developer в ООО «Грустный Роджер».

# Описание
Небольшая Unity-сцена с условным кораблём, реализующая две независимые системы:

**Runtime Wind** — хранение и отображение состояния ветра, UI-индикация направления и относительного угла между кораблём и ветром.

Граница морской локации — предупреждение и обратный отсчёт при выходе корабля за пределы игровой зоны, событие OnLocationExit при истечении таймера.

# Инструкция запуска
*  Клонировать репозиторий:

# Управление
**Действие** - **Клавиша**

Движение вперёд	- W (или стрелка вверх)

Поворот	- A / D (или стрелки влево / вправо)

Изменение направления ветра	- через Inspector компонента Wind

# Часть 1. Runtime Wind
Wind — компонент, хранящий текущее состояние ветра: направление (0–360°) и силу (0–1). Направление задаётся через Inspector.

Wind Indicator (UI) — обновляет текст направления и визуальный индикатор (стрелка). Относительный угол между направлением корабля и ветром вычисляется в Update (или по событию поворота корабля).

# Часть 2. Граница морской локации
Game Area — задаёт границы зоны (через BoxCollider). Определяет, находится ли корабль внутри.

При выходе за границу запускается таймер 1 секунда, после чего появляется предупреждение «Вы покидаете игровую область».

После предупреждения запускается обратный отсчёт 5 секунд.

Если корабль возвращается внутрь - таймеры отменяются, сообщение скрывается.

Если корабль остаётся снаружи до конца отсчёта — вызывается событие OnLocationExit (в текущей реализации — Debug.Log("Location exited")).

Повторные выходы/возвращения обрабатываются корректно: используются флаги состояния и отмена корутин, параллельные таймеры не создаются.

# Что бы я изменил при интеграции в большую игру
Разделение ответственности: вынес бы логику границы в отдельный сервис с интерфейсом, чтобы можно было подменять реализацию (например, разные типы зон: прямоугольная, круглая, полигональная).

Событийная шина: вместо прямых ссылок между компонентами использовал бы ScriptableObject - события или централизованный EventBus.

Погодные пресеты: реализовал бы дополнительное задание с WeatherPresetResolver на основе ScriptableObject с состояниями Clear/Rain/Storm/Fog и автоматическим применением пресета.

Тестирование: добавил бы unit-тесты для логики границы (вход/выход, отмена таймеров) через Unity Test Framework.

UI: заменил бы прямой вывод текста на более гибкую систему c событиями.

Добавил бы локализацию.
